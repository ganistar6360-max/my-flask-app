ABSTRACT 
The Library Management System (LMS) is a web-based application designed to automate the major activities 
of a library, including book catalogue management, member registration, book issue and return, searching, 
overdue tracking and fine management. The system replaces repetitive manual record keeping with a 
centralized database and role-based access. The proposed system is implemented using Python Flask for the 
application layer, MySQL for persistent data storage, and HTML/CSS/Bootstrap/JavaScript for the user 
interface. The project follows the Software Development Life Cycle (SDLC), covering planning, requirements 
analysis, feasibility study, system design, implementation, testing, deployment and maintenance. The report 
documents the requirements, architecture, database design, diagrams, test cases, source code and deployment 
procedure. The design is intentionally modular so that it can be extended with barcode/QR scanning, email 
notifications, online reservations, analytics and cloud deployment. 
Keywords 
Library Automation, Library Management System, SDLC, Flask, Python, MySQL, CRUD, Web Application, 
Database Management, Book Issue and Return

1. INTRODUCTION 
A library maintains a large volume of information about books, members and circulation transactions. In a 
manual system, maintaining registers, searching for books, tracking due dates and calculating fines can be 
time-consuming and error-prone. A computerized Library Management System provides a centralized 
platform for storing, retrieving and updating this information. 
The proposed system is a web application that allows an administrator/librarian to manage books and members 
and to record issue/return transactions. It provides a simple search facility and maintains transaction history. 
The application is designed as an academic reference implementation and can be adapted to a college, school, 
public or departmental library. 
2. PROBLEM STATEMENT 
The manual or semi-manual library process creates difficulties in maintaining accurate records, locating books 
quickly, identifying overdue loans, calculating fines and preparing reports. The project therefore aims to 
develop a reliable web-based system that centralizes library records and automates routine circulation 
operations. 
3. OBJECTIVES 
• Maintain a centralized catalogue of books and categories. 
• Register and manage library members. 
• Provide fast book and member search. 
• Record book issue and return transactions. 
• Automatically identify overdue books and calculate fines. 
• Provide dashboard statistics and basic reports. 
• Protect administrative functions through authentication. 
• Maintain transaction history for accountability. 
• Provide a modular codebase that can be extended in future.

8. REQUIREMENTS ANALYSIS 
8.1 Functional Requirements 
FR-01: Administrator shall authenticate using username and password. 
FR-02: Administrator shall add, edit, delete and search books.

8.2 Non-Functional Requirements 
• Usability: simple navigation and clear validation messages. 
• Performance: normal CRUD/search operations should respond quickly on a properly configured 
local/network deployment. 
• Reliability: transactions should be stored consistently in the database. 
• Security: passwords must be stored as hashes; protected routes require authentication. 
• Maintainability: modular Flask routes, templates and database schema. 
• Scalability: database and application layers can be separated for larger deployments.

9.2 Core Business Rules 
• A book can be issued only when its available quantity is greater than zero. 
• A member must be active to receive a book. 
• One issue transaction represents one book loan. 
• Returning an active loan updates the return date and book availability. 
• Fine = overdue days × daily fine rate. 
• An administrator must authenticate before accessing protected management functions.

DB = { 
    "host": "localhost",

    "password": "YOUR_MYSQL_PASSWORD", 
    "database": "library_db"

FINE_PER_DAY = 5.0 
 
def get_db(): 
    return mysql.connector.connect(**DB) 
 
def login_required(fn): 
    @wraps(fn) 
    def wrapper(*args, **kwargs): 
        if "user_id" not in session: 
            return redirect(url_for("login")) 
        return fn(*args, **kwargs) 
    return wrapper 
 
@app.route("/") 
def index(): 
    return redirect(url_for("dashboard") if "user_id" in session else url_for("login")) 
 
@app.route("/login", methods=["GET", "POST"]) 
def login(): 
    if request.method == "POST": 
        username = request.form["username"].strip() 
        password = request.form["password"] 
        db = get_db() 
        cur = db.cursor(dictionary=True) 
        cur.execute("SELECT * FROM users WHERE username=%s", (username,)) 
        user = cur.fetchone() 
        cur.close(); db.close() 
        if user and check_password_hash(user["password_hash"], password): 
            session["user_id"] = user["user_id"] 
            session["username"] = user["username"] 
            return redirect(url_for("dashboard")) 
        flash("Invalid username or password.", "danger") 
    return render_template("login.html")

@app.route("/issue", methods=["GET", "POST"]) 
@login_required 
def issue(): 
    db = get_db(); cur = db.cursor(dictionary=True) 
    if request.method == "POST": 
        book_id = int(request.form["book_id"]) 
        member_id = int(request.form["member_id"]) 
        due_date = request.form["due_date"] 
        cur.execute("""SELECT available_quantity FROM books 
                       WHERE book_id=%s FOR UPDATE""", (book_id,)) 
        book = cur.fetchone() 
        cur.execute("SELECT status FROM members WHERE member_id=%s", (member_id,)) 
        member = cur.fetchone() 
        if not book or book["available_quantity"] <= 0: 
            flash("Book is not available.", "danger") 
        elif not member or member["status"] != "ACTIVE": 
            flash("Member is not active.", "danger") 
        else: 
            cur.execute("""INSERT INTO book_issues 
                       (book_id,member_id,issue_date,due_date,issued_by) 
                       VALUES(%s,%s,CURDATE(),%s,%s)""", 
                        (book_id,member_id,due_date,session["user_id"])) 
            cur.execute("""UPDATE books SET available_quantity=available_quantity-1 
                           WHERE book_id=%s""", (book_id,)) 
            db.commit() 
            flash("Book issued successfully.", "success") 
    cur.execute("SELECT book_id,title,available_quantity FROM books WHERE 
available_quantity>0") 
    books = cur.fetchall() 
    cur.execute("SELECT member_id,name FROM members WHERE status='ACTIVE' ORDER BY name") 
    members = cur.fetchall() 
    cur.close(); db.close() 
    return render_template("issues.html", books=books, members=members) 
 
@app.route("/return/<int:issue_id>", methods=["POST"]) 
@login_required 
def return_book(issue_id): 
    db = get_db(); cur = db.cursor(dictionary=True) 
    cur.execute("""SELECT * FROM book_issues 
                   WHERE issue_id=%s AND status='ISSUED' FOR UPDATE""", (issue_id,)) 
    issue = cur.fetchone() 
    if not issue: 
        flash("Active issue not found.", "danger") 
    else: 
        today = date.today() 
        overdue_days = max((today - issue["due_date"]).days, 0) 
        fine = overdue_days * FINE_PER_DAY 
        cur.execute("""UPDATE book_issues 
                       SET return_date=CURDATE(), fine=%s, status='RETURNED' 
                       WHERE issue_id=%s""", (fine, issue_id)) 
        cur.execute("""UPDATE books SET available_quantity=available_quantity+1 
                       WHERE book_id=%s""", (issue["book_id"],)) 
        db.commit() 
        flash(f"Book returned. Fine: {fine:.2f}", "success") 
    cur.close(); db.close() 
    return redirect(url_for("dashboard"))

16. SECURITY CONSIDERATIONS 
• Use password hashing rather than storing plaintext passwords. 
• Use parameterized SQL queries to reduce SQL injection risk. 
• Keep the Flask secret key and database credentials outside source control in production. 
• Use HTTPS in production. 
• Implement role-based authorization for multiple user types. 
• Validate and sanitize uploaded/input data. 
• Use secure session configuration and appropriate cookie flags. 
• Back up the database regularly and protect backup files. 
• Update Python packages and the database server regularly.
